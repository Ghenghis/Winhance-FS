CLI Integration Guide — Top 5 Agents on Windows

Audience: Winhance-FS devs Target OS: Windows 11 + PowerShell 7 Goal: Backend-switchable from one launcher

Where the Agents Live in the Repo

Each CLI gets its own subdirectory under .agents/. All five read the same shared context (AGENTS.md, CLAUDE.md) so they have a consistent view of project rules.

C:\Winhance-FS-Repo\
├── .agents\
│   ├── claude\          # CLAUDE.md, hooks, settings.json
│   ├── codex\           # config.toml, profile
│   ├── goose\           # config.yaml + recipes
│   ├── openhands\       # config.toml, microagents
│   ├── kilo\            # .kilocodemodes, custom rules
│   ├── shared\
│   │   ├── mcp-servers.json     # reused across all five
│   │   ├── system-prompt.md     # common preamble
│   │   └── task-routing.yaml    # which CLI for which task
│   └── launcher\
│       ├── winhance-agent.ps1   # the unified entry point
│       └── docker-sandbox.ps1   # microVM wrapper
├── AGENTS.md            # universal — Codex, Goose, Kilo, OpenHands read this
├── CLAUDE.md            # Claude Code specific
└── ...
Why two manifest files? Anthropic standardized on CLAUDE.md; the open-source ecosystem (Codex, Goose, Kilo, OpenHands) standardized on AGENTS.md. Keep both. Make CLAUDE.md a one-line file that @-imports AGENTS.md so there's a single source of truth. 
# C:\Winhance-FS-Repo\CLAUDE.md
# See @AGENTS.md for project rules — this file just delegates.
@AGENTS.md

Shared Context Files

AGENTS.md — Universal Project Brief

Read by Codex, Goose, Kilo, OpenHands automatically. Used by Claude through the import in CLAUDE.md.

# Winhance-FS · Agent Instructions

## Project
.NET 8 WPF Windows file manager + system optimizer. Multi-language:
C# (~616 files), Rust (4 nexus_ crates), Python (analytics).

## Build / Test
- Build:  dotnet build Winhance.sln -c Release
- Test:   dotnet test Winhance.sln -c Release --no-build
- Required: 0 errors / 0 warnings before any commit

## Hard Rules
- NEVER add code comments unless the WHY is non-obvious
- NEVER restore TODO / FIXME / Stub / Demo / Fake tokens in src/
- NEVER bypass git hooks (--no-verify)
- ALWAYS prefer editing existing files over creating new ones
- ALWAYS run `dotnet build` before claiming success

## Critical Files
- src/Winhance.WPF/App.xaml.cs — DI composition root (P0 fix pending here)
- Directory.Build.props — global NoWarn (treat as debt, do not extend)
- docs/audit/index.html — read this before opening a new feature

## Backend-switchable Stack
Agents may be invoked via .agents\launcher\winhance-agent.ps1 with:
  -Backend Claude | Codex | Goose | OpenHands | Kilo

shared/mcp-servers.json — Common MCP Pool

All five CLIs point at the same MCP servers so they share filesystem, search, and memory access.

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem",
               "C:\\Winhance-FS-Repo"]
    },
    "sequential-thinking": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-sequential-thinking"]
    },
    "project-mcp": {
      "command": "node",
      "args": ["C:\\Winhance-FS-Repo\\.agents\\shared\\project-mcp\\index.js"]
    }
  }
}

1 · Claude Code (default driver)

Install

# Per Anthropic docs — Claude Code CLI
npm install -g @anthropic-ai/claude-code

# OR via standalone installer:
iwr https://claude.ai/install.ps1 -UseBasicParsing | iex

claude --version   # sanity check

Project Config

# C:\Winhance-FS-Repo\.agents\claude\settings.json
{
  "mcpServers": "@../shared/mcp-servers.json",
  "hooks": {
    "PostToolUse": [{
      "tool": "Write|Edit",
      "command": "dotnet build Winhance.sln -c Release --no-restore"
    }]
  },
  "permissions": { "allow": ["Read", "Edit", "Write", "Bash(dotnet*)", "Bash(git status)"] }
}

Run

cd C:\Winhance-FS-Repo
claude
# or scripted:
claude -p "fix the DI gap in src/Winhance.WPF/App.xaml.cs per docs/audit/12-di-registration.html"

Project memory lives in CLAUDE.md (already created above with the @AGENTS.md import). Subagents and slash commands live in .claude/agents/ and .claude/commands/.

GOOSE_MODEL: claude-opus-4-7

    enabled: true
    bundled: true
  developer:
    enabled: true                    # shell + file edit + screen capture
  computercontroller:
    enabled: false                   # keep off unless needed
  jetbrains:
    enabled: false

# MCP servers from the shared pool:
mcp_servers:
  sequential-thinking:
    type: stdio
    command: npx
    args: ["-y", "@modelcontextprotocol/server-sequential-thinking"]

Run

cd C:\Winhance-FS-Repo
goose session                        # interactive REPL
goose run --instructions audit-task.md  # one-shot
goose run --recipe recipes/fix-di-gap.yaml

Goose recipes are YAML task definitions — reuse them for repeated workflows (e.g. "audit-then-PR", "warning-sweep"). Best fit when you want free local-model bulk work via Ollama.

Kilo's Agent Manager gives you the "20 agents" workflow — multiple sessions each in their own git worktree, supervised from one terminal pane. Best when work splits cleanly into independent chunks (per-feature audits, per-file refactors).

The Unified Launcher — Backend Switch in One Flag

# C:\Winhance-FS-Repo\.agents\launcher\winhance-agent.ps1
param(
  [ValidateSet("Claude", "Codex", "Goose", "OpenHands", "Kilo")]
  [string]$Backend = "Claude",

  [string]$Task,
  [switch]$Sandbox,
  [switch]$ReadOnly
)

$repo = "C:\Winhance-FS-Repo"
$cfgDir = "$repo\.agents\$($Backend.ToLower())"

if ($Sandbox) {
  # Hand off to Docker Sandbox microVM (see Doc 03)
  & "$repo\.agents\launcher\docker-sandbox.ps1" -Backend $Backend -Task $Task
  return
}

switch ($Backend) {
  "Claude"     { & claude $Task }
  "Codex"      { & codex exec --profile $cfgDir $Task }
  "Goose"      { & goose run --config $cfgDir\config.yaml --instructions $Task }
  "OpenHands"  { & openhands cli --config $cfgDir\config.toml --task $Task }
  "Kilo"       { & kilo --modes $cfgDir\.kilocodemodes $Task }
}

Usage

# Daily driver:
.\.agents\launcher\winhance-agent.ps1 -Backend Claude -Task "work on the audit P0 list"

# Free local-model batch:
.\.agents\launcher\winhance-agent.ps1 -Backend Goose -Task "./recipes/warning-sweep.yaml"

# Autonomous overnight job in a microVM:
.\.agents\launcher\winhance-agent.ps1 -Backend OpenHands -Task "close all P2 items" -Sandbox

# .agents/shared/task-routing.yaml — machine-readable
routes:
  - match: { type: refactor, scope: multi-file }
    backend: Claude
  - match: { type: audit }
    backend: Claude
  - match: { type: autonomous, duration: long }
    backend: OpenHands
    sandbox: true
  - match: { type: bulk, cost: low }
    backend: Goose
    model: ollama/qwen2.5-coder
  - match: { type: parallel-fanout }
    backend: Kilo
    mode: orchestrator
  - match: { type: test-fix-loop }
    backend: Codex

Shared MCP Pool — One Server Bank, Five Clients

All five CLIs speak MCP. Run the heavy MCP servers (filesystem, project-mcp, sequential-thinking) once on the host, then point every CLI's config at the same set. This avoids duplicate indexing, gives every agent the same code search, and keeps memory in one place.

Pattern: the same .agents/shared/mcp-servers.json is referenced from Claude's settings.json, Goose's config.yaml (under mcp_servers:), Codex's config.toml (under [mcp_servers.*]), OpenHands' config, and Kilo's mode definitions. Update once, all five inherit.

Daily Workflow Example

# Morning: kick off a long autonomous job in a sandbox
.\.agents\launcher\winhance-agent.ps1 -Backend OpenHands `
  -Task "close P2-1 through P2-3 from the handoff" -Sandbox

# Meanwhile, do interactive work on the P0 DI fix:
.\.agents\launcher\winhance-agent.ps1 -Backend Claude `
  -Task "wire up AddFileManagerServices() in App.xaml.cs"

# When OpenHands signals, review its PR draft with Aider (architect mode):
aider --architect --browser

# End of day, fan out the warning-sweep across 4 worktrees:
.\.agents\launcher\winhance-agent.ps1 -Backend Kilo `
  -Task "orchestrator: 4-way fan-out on src/Winhance.WPF/Features/{FileManager,Optimize,Customize,SoftwareApps}"

Troubleshooting

SymptomLikely CauseFix
Two agents fight over the same fileBoth writing to the same worktreeUse Kilo Agent Manager or git worktrees; one branch per agent.
Build green locally, red in sandboxSandbox missing .NET 8 SDKPre-install SDK in the microVM base image (Doc 03).
OpenHands hangs on first promptDocker Desktop not runningStart Docker Desktop or set runtime=local.
Codex won't accept the project contextAGENTS.md too longTrim to < 200 lines; move detail to feature-folder READMEs.
Goose Ollama model slowCPU inferenceSwitch GOOSE_PROVIDER to a cloud one for that session, or move Ollama to GPU.
Kilo modes ignored.kilocodemodes not at repo rootSymlink from .agents/kilo/.kilocodemodes to repo root.
